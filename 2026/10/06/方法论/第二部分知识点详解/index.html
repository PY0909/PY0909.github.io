§A 数据工程（第三章的地基）

A.1 三种原始数据格式与适配器

【通俗】 三个数据集来自三个世界： MetroPT-3 是一张大 Excel 表（每行一个时刻、每列一路信号）；C-MAPSS 是一摞”每台发动机一份”的文本表；TEP 是 R 语言的数据文件（RData）。适配器（adapter）= 把三种方言翻译成同一种”普通话”（统一张量协议）的代码。

【公式】 无公式，但有”翻译目标”的形式契约：任何数据集最终都产出窗口样本
(Xobs,Tobs,Mobs,Tq,Yq,Mq,context,r)(X_{obs}, T_{obs}, M_{obs}, T_q, Y_q, M_q, \text{context}, r)(Xobs​,Tobs​,Mobs​,Tq​,Yq​,Mq​,context,r)
（历史值/历史时间/历史掩码/查询时刻/查询目标/目标掩码/工况上下文/风险标签），其中 Xobs∈RL×NX_{obs}\in\mathbb{R}^{L\times N}Xobs​∈RL×N、Mobs∈{0,1}L×NM_{obs}\in\{0,1\}^{L\times N}Mobs​∈{0,1}L×N。

【专业】 实测格式（均已对照原始文件核实）：

🔍 小白详解：文件格式与量纲术语
CSV：逗号分隔文本，Excel 能开，一行=一个时刻（人能读、pandas 一句话加载）。txt（C-MAPSS）：空格分隔、无表头，26 列数字。RData/RData+XDR：R 语言的数据文件（二进制）——XDR 是”跨机器字节序标准”（大端=高位字节在前），Python 不认识所以要自写解析器。npz：numpy 的压缩包（多个数组打一个文件、按键名取）。SHA256SUMS.txt：官方给出的”每个文件的指纹清单”，下载后可校验没被篡改。
模拟量 vs 开关量（对应 Part1 Q13-二）：连续实数传感器（温度/压力/电流）vs 0/1 状态位（启停/阀门/报警）——处理不同（z-score vs 保持原值）。大端字节序：数字 258 在内存里是 [1,2]（高位在前）还是 [2,1]（低位在前）——XDR 规定大端，解析器按此拆字节。unit（单元）：一条独立时间线的名字（一台引擎/一次仿真/一个连续运行段）。

A.2 unit（单元）与窗口目录

【通俗】 “unit”=数据天然独立的单位：一台发动机、一次仿真、一个连续运行段。窗口（卡片）绝不能跨 unit 切——跨了就是把 A 的未来喂给 B 当历史（泄漏）。

【公式】 窗口目录：对每个 unit uuu（长度 TuT_uTu​），
Wu={(u,s):s=0,s0,2s0,…, s+Lh+Lp≤Tu}W_u = \{(u, s) : s = 0, s_0, 2s_0, \dots,\ s + L_h + L_p \le T_u\}Wu​={(u,s):s=0,s0​,2s0​,…, s+Lh​+Lp​≤Tu​}
s0s_0s0​ 为步长（stride）。每个窗口样本只读取本 unit 内的切片。

【专业】 三个数据集的 unit：C-MAPSS=engine；TEP=faultNumber:simulationRun（同一故障的第 k 次仿真内部有时序依赖，跨 run 独立）；MetroPT-3=segment（在间隔 > 3×train 中位间隔处断开切出的连续运行段；GAP_MULTIPLIER=3.0 在 metropt.py L52，阈值在 datasets.py L990 由 train 段的中位间隔计算——用 train 统计而非全集，又是一条防泄漏细节）。协议明文规定”窗口不得跨 unit、mask 生成器不得读取故障标签”（plan/experiment-protocol.md L26）。

A.3 确定性协议与 SHA256 哈希链

【通俗】 “确定性”= 同样的代码+同样的数据跑一百遍，得到同一个划分、同一套掩码。靠什么保证？给每个中间产物发一张指纹（SHA256 哈希），指纹对得上才允许进下一步——像流水线上的封条。

【公式】 SHA256 是函数 h:{0,1}∗→{0,1}256h:\{0,1\}^* \to \{0,1\}^{256}h:{0,1}∗→{0,1}256，性质：①确定性（同输入必同输出）；②雪崩性（输入改 1 bit，输出约一半位翻转）；③抗碰撞性（实际找不到两个不同输入同指纹）。仓库的哈希链：
raw_sha→partition_sha→timeline_sha→window_catalog_sha\text{raw}\_sha \to \text{partition}\_sha \to \text{timeline}\_sha \to \text{window\_catalog}\_sharaw_sha→partition_sha→timeline_sha→window_catalog_sha
每一环把上一环指纹拼进自己的哈希输入——篡改任何一环，后面所有指纹对不上。

【专业】

  • MetroPT-3 v2 协议全链（industrial/metropt.py L443–515）：raw/partition/timeline/window_catalog 四级 SHA；划分=唯一时间戳组时序 50/20/30；切段=间隔 >3×train 中位间隔处断开（GAP_MULTIPLIER=3.0，L52）；窗口以 segment 为 unit。
  • 归一化统计也是协议产物：train-only z-score 统计量存成 artifact（metropt_v2_stats_artifact），带自己的 SHA——别人复现时先对指纹再对数字。
  • 归一化公式（train-only）：x′=(x−μtrain)/σtrainx' = (x-\mu_{train})/\sigma_{train}x′=(x−μtrain​)/σtrain​，仅对 7 个连续通道；开关通道保持 0/1（协议明文，代码注释 L601–605）。

    🔍 小白详解：SHA256——为什么一个哈希能当”身份证”
    哈希函数是什么：把任意长的输入（一个文件、一串文字）压成固定 256 位（64 个十六进制字符）的”指纹”。三个性质使它能当身份证：①确定性——同一输入永远得到同一指纹（可复现的根基）；②雪崩效应——输入改 1 个字节，指纹约一半的位翻转（改了就一定看得出来）；③抗碰撞——实际不可能找到两个不同输入有相同指纹（指纹对得上=内容一定一样）。
    手算直觉：”hello” 的 SHA256 = 2cf24dba…；”hello!”（多一个感叹号）= ce06092f…——完全不同。所以”比较两个大文件是否相同”不需要逐字节比，比 64 个字符的指纹即可。
    哈希链：你的仓库把 raw 数据的指纹拼进划分产物再做哈希，划分产物的指纹拼进窗口目录再做哈希……任何一环被改，后面所有指纹对不上——篡改无法”只改中间一环”。
    你会在哪见到它：manifest 的 split_sha256/normalization_sha256/mask_sha、mask bundle 的 content_sha256、window_id——全是同一思想：用指纹代替”我发誓没改过”。

A.4 timeline-first 掩码 vs 逐窗口掩码

【通俗】 旧做法：每张卡片各自随机决定哪里缺——同一时刻在卡片 A 里缺、在卡片 B 里不缺，物理上自相矛盾。新做法：先给整条时间线（每 unit 一张长掩码）决定哪里缺，所有窗口从这条长掩码上切——同一时刻在所有窗口里观测状态一致，像真实世界。

【公式】 设 unit uuu 的时间线掩码 Mu∈{0,1}Tu×NM_u \in \{0,1\}^{T_u \times N}Mu​∈{0,1}Tu​×N（一次性生成），窗口 (u,s)(u,s)(u,s) 的历史掩码是切片：
Mobs(u,s)=Mu[s:s+Lh],Mq(u,s)≡1M_{obs}^{(u,s)} = M_u[s : s+L_h], \qquad M_q^{(u,s)} \equiv \mathbf{1}Mobs(u,s)​=Mu​[s:s+Lh​],Mq(u,s)​≡1
关键不变式：查询目标掩码 MqM_qMq​ 恒为全 1（目标永不被缺失）——问题语义是”看不完整的历史，预测完整未来”。

【专业】

  • 实现（experiments/masks.py）：TimelineMaskBundle（L59–75）的 masks 字典映射 engine_id → uint8 数组；TimelineMaskedWindowDataset（L373 起）的 __getitem__ 按 (unit, start) 切片，只改 M_obs/X_obs。
  • 掩码种子派生防串线：每个 unit 的随机流由 SHA256("schema|dataset|split|mechanism|mask_seed|engine_id") 的前 8 位十六进制派生（L79–89）——unit 之间、split 之间随机流互不污染，且完全可复现。
  • 四机制（industrial/missing.py，已核实）：random=独立伯努利；low_rate=周期网格；block_offline=整段置零；mixed=low_rate(keep 0.80) × 随机 dropout × block(0.25) 按位相乘（L88–107）。

B.2 mask-safe 卷积归一化（kafnet_encoder.py L377–387，核实）

【通俗】 问题：卷积窗口里有”填充 0”（其实是缺失），卷出来的平均被 0 拉低——模型把”缺失”误读成”数值低”。解法：分母只数有效邻居。

【专业】 对比错误做法”先 z-score 全序列再卷积”：缺失填充值会进入均值/方差与卷积，且越缺失越偏。这里支撑集计数 support 保证分母=真实观测数——缺失越多不改变估计的无偏性。之后所有路径（KAF 池化、patch 统计）都只在这份 observed_values 上做。这是论文 3.5.1 小节的公式素材。

🔍 小白详解：mask-safe 卷积数值走查（为什么 0 填充不污染）
设一条通道序列（k=3 窗口）：值=[**, 5, **]（中间观测=5，两侧缺失），掩码=[0,1,0]。填充值若是”脏的”（比如缺失处残留 −3）：

  • 错误做法（先对全体卷积再归一化）：卷积窗口读到 [−3,5,?]，填充值混进平均 → 输出被脏值拉偏；
  • mask-safe 做法（公式逐项）：分子=num=Conv(masked 值)（缺失位先乘 m 变 0，贡献 0）；分母=支撑计数 sup=0+1+0=1（只数有效邻居）；归一化=num/max(sup,1)=5/1=5——缺失位的脏值根本进不了计算。若三点全有效 [4,5,6]：sup=3，num≈(4+5+6)·w/3（w 为可学权重）→ 正常的 3 点加权平均。
  • 全缺失窗口（sup=0）：输出强制 0（torch.where(support>0,…)）——不产生垃圾数。
    一句话：分子只加”有效值”，分母只数”有效个数”→ 缺多少都不偏。这就是”缺失感知”在数据进入模型前的第一道防线。

D.4 validate_results 验收（validate_results.py，核实）

【专业】 对每个 key 检查：run 目录与产物齐全 → key 七段与 manifest 身份一致 → point 指标有限值 → test_evaluation_count==1 → 组内公平性（同 protocol 指纹 + 同 matrix SHA）→ 输出 JSON verdict，非零退出码作 CI 门禁——不通过的矩阵进不了论文。预检配套：check_pilot_environment.py 记录 git 状态/数据 SHA/依赖版本/GPU/磁盘，双机比对（compare_reports）保证”本地与 AutoDL 跑的是同一个实验”。

🔍 小白详解：契约、扰动测试与验收链——三个”防作弊装置”串起来
①模型契约（插座制）：所有模型实现同一组方法名（predict_point/loss；概率类再加 sample_flat/batch_nll）——评估脚本只认方法名不认模型，加新基线不用改评估代码。这保证的是：所有模型的指标由同一段代码算出，不存在”你的 MAE 和我的 MAE 算法不一样”。
②扰动测试（防偷看答案的行为测试）：把 batch 里的目标字段（y_flat/M_q/rul）替换成随机数，再跑一次前向——输出必须一字不变。为什么强：不管你代码怎么重构，只要模型真的读了目标字段，输出就会变，测试立刻红——比”代码审查保证不看”可靠得多。
③验收链（机器把关）：validate_results 逐 key 检查（产物齐/身份一致/指标有限/test 只评一次/组内公平指纹一致），非零退出码=不通过——不通过的矩阵进不了论文。三者连读：契约保证”同一把尺”，扰动测试保证”没抄答案”，验收链保证”交上来的卷子完整且是自己写的”。
C/D 部分其余名词速查：scientific key=run 的身份证（七段：数据集|赛道|模型|变体|头|条件|种子，任何配置变一项 key 就变）；dry-run=只打印计划不训练；smoke=小预算走全流程；tune=全预算调参但不建 test loader（调参实验物理上接触不到测试集）；manifest=run 的出生证（身份/配方/协议指纹/耗时/参数量全在内）；tuning_only 标记=调参产物永不进正式表。

E.2 三张核心图的生成要点（matplotlib）

  1. 鲁棒性曲线：x=缺失率 {0,10,30,50,70}%，y=MAE（或退化率%，公式见第一部分详解 §1.3），每模型一线；误差棒=3 seeds ±std。
  2. 预测区间图：选一个测试窗口，画 y_true 曲线、μ^\hat\muμ^​ 曲线、[q0.025q_{0.025}q0.025​, q0.975q_{0.975}q0.975​] 阴影带、缺失位置竖线标注（从 M_obs 取）——样本来自明细子集（C.4）。
  3. 风险时间线：风险分数曲线 + 验证集分位阈值横线 + 真实故障区间阴影 + Lead time 标注（公式见第一部分详解 §1.7）。
  4. 训练曲线：从每个 run 的 history.json 画 epoch×{train loss, valid MAE/crps} 双线——既是过拟合检查（第一部分详解 §5.4），也是论文附录”训练稳定性”的现成配图。

🔍 全文档补遗——易漏术语速查（审查后补充）

  • 伯努利分布：单次掷硬币的 0/1 分布（P(1)=p）——random 掩码每个格就是一次伯努利试验。
  • Xavier 初始化：权重按”输入维度”缩放的随机初始化（W∼U[−6/(din+dout),… ]W\sim U[-\sqrt{6/(d_{in}+d_{out})},\dots]W∼U[−6/(din​+dout​)​,…] 或同方差正态）——使前向激活的方差逐层稳定；gain=0.05 再乘 0.05=刻意让初始输出接近 0。
  • one-hot：只有第 i 位是 1、其余全 0 的向量——“类别 i”的最朴素编码；Embedding=可学习的 one-hot×矩阵（省去乘法直接查行）。
  • einsum：爱因斯坦求和约定——用下标字符串声明张量缩并（"blk,bld->bk"=按 t 求和），比手写 matmul/transpose 不易错。
  • rfft/irfft：实数信号的快速傅里叶变换与其逆变换（rfft 只返回一半频谱，因实信号谱共轭对称）。
  • cdist：计算两组向量两两之间的距离矩阵（torch.cdist(X,Y)→[n,m]）——Energy Score 的成对项用它。
  • lgamma：伽马函数的对数（Γ\GammaΓ 是阶乘在实数上的推广）——Student-t 密度的归一化常数 log⁡Γ(ν+12)−log⁡Γ(ν2)\log\Gamma(\frac{\nu+1}{2})-\log\Gamma(\frac{\nu}{2})logΓ(2ν+1​)−logΓ(2ν​) 用它算，数值稳定。
  • batch_first：PyTorch RNN 的参数——输入按 [batch, seq, feature] 排列（默认是 [seq, batch, feature]，(batch_first=True) 更符合直觉）。
  • state_dict：PyTorch 模型的”参数名→张量”字典——checkpoint 存的就是它；加载用 load_state_dict。
