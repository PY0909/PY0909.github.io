§1 阶段 1：训练循环解剖（以 train_metropt_kaf_profiti.py 为解剖标本）

1.1 PyTorch 训练循环的八步骨架（run_epoch，L48–69 逐行）

【通俗】 所有深度学习训练都是一个循环八步曲：拿数据 → 前向 → 算损失 → 清梯度 → 反向传 → （裁剪）→ 更新 → 记账。区别只在每步的”方言”。

【代码】（L54–68，逐行对应）

【专业】 四个初学者必踩的坑，这 15 行里全有正确示范：

  • zero_grad(set_to_none=True)：PyTorch 梯度是累加的（.grad +=），不清零则上一 batch 的梯度混进来——默认 batch 间梯度全部叠加，模型看似在”动量狂奔”。set_to_none=True 比 zero 更省内存（直接置 None）。
  • model.train(train)：切换 Dropout/BatchNorm 行为；验证忘记 eval() 是”验证 loss 抖动”的头号原因。
  • torch.enable_grad()/no_grad() 上下文（L52–53）：验证时不建计算图，省显存又提速。
  • float(loss.detach().cpu())：直接 += loss 会把整张计算图拽住不放 → 显存泄漏；detach() 切断引用再记账。

    🔍 小白详解：读懂八步骨架需要的三块前置知识
    ①张量与自动微分（PyTorch 的核心机制）：张量=带”记账本”的多维数组——每次对它做运算，记账本记下”我是由谁算出来的”。loss.backward() 沿记账本反向用链式法则算出每个参数的梯度，写进 param.grad。所以：前向=记账，backward=算账，optimizer.step()=按账改参数。记账本就是”计算图”——detach() 的意思是”这段历史我不要了”（记账本剪断，数值保留）。
    ②广播（broadcasting）：形状 [B,1,N] 与 [B,L,N] 相运算时，长度 1 的维度自动”复制”到 L——掩码 [B,1,N]×值 [B,L,N] 就是靠它实现”对每一路传感器统一乘掩码”。
    ③梯度裁剪的时机：必须在 backward() 之后、step() 之前（L62 的位置）——裁剪的对象是刚算出来的梯度。
    一张表对应八步与”账本”：zero_grad=撕新账页；forward=记账；backward=算账；clip=检查账本异常；step=按账改参；detach=复印数字撕账本。看懂这句话，八步骨架就不是八句咒语而是八件自然的事。

1.6 M_obs=0 实验的设计原理

【公式】 mask 的三层语义（本实验要验证的第一层）：

  1. 输入侧：Mobs=0M_{obs}=0Mobs​=0 的位置 XobsX_{obs}Xobs​ 原值仍在张量里（张量不因 mask 清零）——模型”能不能看到”取决于后续模块是否自觉乘 mask 或做 mask-safe 归一化；
  2. 损失侧：loss 乘 mq_flatmq\_flatmq_flat → 目标缺失位不贡献梯度；
  3. 契约侧：FORBIDDEN_BATCH_FIELDS 保证模型读不到目标侧任何字段。

【专业】 这个实验（手动把某通道 M_obs 置 0，观察预测变化）是理解全仓库的”钩子”：你会看到 v2 编码器输出几乎不变（因为 mask-safe conv + TTKMN 权重乘 m），而基线 FFGRU 输出显著变化（前向填充把填充值当真值）——一行实验胜过十页文档，这就是”缺失感知”三个字的实测含义。

2.1 不对称 mask 实验（验证 mask-safe conv 与 TTKMN）

【公式】 设计：构造同一 batch 的两个版本——A 左半观测右半缺失、B 右半观测左半缺失（MAM_AMA​ 与 MBM_BMB​ 左右翻转）。mask-safe 的预言：
f(X,MA)≠f(X,MB)且两者各自只依赖自己的观测侧f(X, M_A) \ne f(X, M_B) \quad \text{且两者各自只依赖自己的观测侧}f(X,MA​)=f(X,MB​)且两者各自只依赖自己的观测侧
更强的对照：把缺失位置的 XXX 填成任意垃圾值 ccc，则 f(X垃圾,MA)=f(X,MA)f(X_{垃圾}, M_A) = f(X, M_A)f(X垃圾​,MA​)=f(X,MA​)——输出对缺失位置的取值完全不变。

【专业】 这就是第二部分 §B.2 公式 x^t=numt/max⁡(supt,1)\hat x_t = \text{num}_t/\max(\text{sup}_t,1)x^t​=numt​/max(supt​,1) 的行为化证明：分子是 masked 值的卷积、分母只数有效邻居 → 缺失位取什么值根本进不了计算。实验里若发现”填垃圾值输出变了”，你就抓到了一个真 bug（先查自己 demo 写对没有，再查是不是旧版 kst_light 走了 MultiScale 无 mask-safe 的路径）。

三步读法（任何基线都适用）：①读类头部的 ADAPTER/SOURCE_IDENTITY 字符串——它声明”吃什么输入、忠实复现了谁的什么机制”；②读 encode_history——历史怎么变成 [B,H] 向量（这一步是基线的全部个性）；③读输出头——统一 LinearPointHead（P·N 个数），不看。
GRUD 数值走查：某通道最后观测 x_last=2.0，已缺失 δ=5 步，train 均值（fill）=0，衰减率 softplus(r)=0.97：
γ=exp(−0.97×5)=exp(−4.85)≈0.0078 → 缺失处的输入 x^=γxlast+(1−γ)×0≈0.016\hat x=\gamma x_{last}+(1-\gamma)\times0\approx0.016x^=γxlast​+(1−γ)×0≈0.016——几乎衰减到均值（δ 大时旧值不再被信任）。若 δ=0.5：γ=exp(−0.485)≈0.62 → x^=0.62×2.0=1.24\hat x=0.62\times2.0=1.24x^=0.62×2.0=1.24（刚缺不久，还比较信旧值）。
与原版 GRU-D 的两处差异（引用必声明）：原版衰减率是逐特征仿射 e−max⁡(0,Wγδ+bγ)e^{-\max(0,W_\gamma\delta+b_\gamma)}e−max(0,Wγ​δ+bγ​) 且隐状态也衰减；适配版是每传感器一个标量率、无隐状态衰减。数值上：适配版更保守（隐状态不受缺失间隙扰动），弱于原版的建模能力——所以你赢它时的表述是”在统一协议的适配实现上”，不是”赢了 GRU-D 原版”。
ODE-RNN 的 Euler 演示：h←h+Δt⋅tanh⁡(Wh)h\leftarrow h+\Delta t\cdot\tanh(Wh)h←h+Δt⋅tanh(Wh)——时间间隙 Δt=10 时，展开 10 次乘法链；梯度反向传播同样乘 10 次 → 范数指数放大（实测 6.6e7）→ 必须 clip（第三部分详解 §1.5）。

§5 阶段 5：门禁与统计

5.1 stage-gates 门禁机制

【专业】 plan/stage-gates.md（已核实原文）注册 D0–D5 门禁的状态机：open / closed / stale 三态，YAML 注册表（schema ch3-gates-v1）是唯一结构化记录，当前 D0–D2 已关闭、D3–D5 open。evidence record 固定字段：gate_id / check_id / previous_status / new_status / depends_on / input_sha_set / command / exit_code / evidence_relpath / evidence_sha256 / checked_at_utc / supersedes。最有价值的机制是 stale 传播：gate-specific validator 每次重算排序后的 canonical input_sha_set，与已关闭记录不一致 → 该 gate 自动改 stale、checkbox 恢复 [ ]，且沿依赖图递归标记全部下游 gate、非零退出码阻断继续——输入变了，门禁不可能”假装还关着”。心智模型：门禁=纯函数 gate(input_sha_set, evidence) -> {closed, stale}，与你 validate_results 的退出码、CI 的 status check 同构；stale 记录用 supersedes 指向旧记录 SHA，只追加不覆盖——证据链本身也是 append-only 的。

5.2 GO/NO-GO 判定

【专业】 plan/ch3_central_go_no_go.json 的判定结构：中心条件（MetroPT-3 mixed@0.30）上 kst_light_v2 vs 全部基线的指标对比+统计判据，结论 GO（test MAE 0.2131 全场最低、领先 li_tcn 17.3%，六 run validator 全绿——git 5f08fe6）。学习点：GO/NO-GO 是”预注册的决策规则”——先写清楚什么算过（领先幅度+验收全绿），跑完只对照不解释。这防止”结果出来再找说法”，与风险区间的预注册同一思想。

5.3 bootstrap 配对重采样（experiment-protocol.md L147，协议原文已核实）

【公式】 协议规定的配对比较显著性方法：

  1. 对自然单位（FD004=engine、TEP=faultNumber:simulationRun）有放回抽样得到重采样集合 U(b)U^{(b)}U(b)，两个模型共用同一份抽样索引（配对！）；
  2. 每个重采样内按充分统计量（绝对误差和、平方误差和）重算全局 MAE/RMSE；
  3. 三个 seed 的估计取算术均值，形成一次 bootstrap replicate；
  4. 重复 b=1..Bb=1..Bb=1..B 得指标差 Δ(b)\Delta^{(b)}Δ(b) 的经验分布 → 置信区间/ppp 值：
    CI95%=[Δ(⌊0.025B⌋), Δ(⌊0.975B⌋)],p=1B∑b1[Δ(b)≤0]CI_{95\%} = \big[\Delta^{(\lfloor 0.025B\rfloor)},\ \Delta^{(\lfloor 0.975B\rfloor)}\big], \qquad p = \frac{1}{B}\sum_b \mathbf{1}[\Delta^{(b)} \le 0]CI95%​=[Δ(⌊0.025B⌋), Δ(⌊0.975B⌋)],p=B1​b∑​1[Δ(b)≤0]

【专业】 为什么这样设计：①unit 级重采样（不是窗口级）——同一 engine 的窗口相关，独立重采样单位必须是 unit；②共用索引——配对 bootstrap 消除”抽样运气”差异，只留模型差异；③充分统计量重算——不必重算逐窗口误差，只存和即可（与 accumulator 哲学同源）；④三 seed 平均后再 bootstrap——把 run 间波动也折进区间。这比第一部分详解 §5.2 的 Wilcoxon 更适合”逐窗口强自相关+分层结构”的数据——两套方法论文里可二选一并说明理由。

🔍 小白详解：bootstrap 配对检验的数值演示（5 个 unit 迷你版）
设 5 台引擎，两模型各自 MAE（unit 级）：A=[0.30,0.22,0.28,0.25,0.20]，B=[0.34,0.21,0.33,0.26,0.22]。配对差 d=A−B=[−0.04,+0.01,−0.05,−0.01,−0.02]（A 赢 4 台）。
一次重采样：有放回抽 5 个 unit（如抽到 {2,2,4,1,3}）→ d’=[+0.01,+0.01,−0.01,−0.04,−0.05] → 均值 −0.016。重复 10000 次 → 得到 10000 个重采样均值的分布（bootstrap 分布）。
读结果：若分布的 2.5%~97.5% 分位是 [−0.045, −0.005]——整个区间在 0 左边 → “A 更好”在 95% 置信下成立；若区间横跨 0 → 不能下结论。p 值=分布里 ≥0 的比例（比如 3%）。
为什么 unit 级重采样：同一引擎的窗口高度相关（当作独立会高估样本量）；引擎才是独立抽样单位。为什么配对：每次重采样里 A、B 用同一批引擎——引擎难度的影响被抵消，剩下的差异全是模型差异。为什么充分统计量：重采样只需”该 unit 的误差和/个数”两个数即可重算 MAE，不必重算逐窗口。

附：与前两篇的关系

🔍 全文档补遗——易漏术语速查（审查后补充）

  • BPTT（沿时间反向传播）：RNN 的训练方式——把网络按时间步展开成很深的链再反向传播；链越长梯度越容易爆炸/消失。TCN 的卖点之一就是”梯度不沿时间链式”（无 BPTT）。
  • CUDA：NVIDIA GPU 的编程运行时——“CUDA 版本”指它的驱动/API 版本，manifest 的 preflight 会记录（复现环境必核对）。
  • 预热（warm-up run）：正式计时前先空跑几次——排除首次调用触发的 CUDA 内核编译、内存分配等一次性开销。
  • state_dict：模型的”参数名→张量”字典；torch.save(model.state_dict()) 存、load_state_dict 取。
  • argparse：Python 标准库，解析命令行参数（--epochs 80 → args.epochs=80）——所有入口脚本的第一段。
  • numel：张量的元素总个数——数参数量用 p.numel()。
  • 梯度反转层（gradient reversal）：前向恒等、反向把梯度取负——特征学习器被”逼着”骗过域判别器，从而学到域不变特征（刘琰论文的对抗迁移核心件）。
  • MAML：模型无关元学习——找一组”离所有任务都近”的初始化，使新任务几步梯度就能适应。
